# Projects and Areas of Exploration

This page distinguishes completed practical work from active learning projects and early concepts.

## Practical Project Experience

### University Library Management System

I personally built a library management system for a reputed university. The latest status I shared was that the system had entered beta testing and might be implemented by the university.

This is one of my most successful projects because it moved beyond an isolated exercise toward possible use by a real institution. Its current deployment status should be reconfirmed before making a stronger public claim.

### Clothing Buy-and-Sell Platform Deployment

An IT company needed a buying-and-selling platform for a clothing brand. I took an existing open-source solution, adapted and implemented it for their needs, and deployed it on their server.

This was not a system built entirely from scratch. Its value was in understanding an existing project sufficiently to configure, adapt, and deploy it in a real environment.

### Sparkle Raspberry Pi Server

**Sparkle** is my Raspberry Pi 4B server running Debian GNU/Linux.

Through it, I have worked with:

- Linux installation and administration;
- SSH and key-based authentication;
- multiple users and roles;
- groups, permissions, sudo, and ACLs;
- a shared workspace;
- local networking;
- security updates and Fail2Ban;
- monitoring and diagnostics;
- service management;
- a custom dynamic login welcome message; and
- documentation for rebuilding and maintaining the server.

The server is a practical learning environment, not a claim of enterprise-scale infrastructure experience.

## Research and Prototype Concepts

### Secure Anonymous Communication

I am researching the foundations for a secure anonymous communication prototype that could run partly on Raspberry Pi infrastructure.

One design idea is a short-lived invitation code that can be shared without exposing a recognizable website link, alongside more conventional link or QR options.

This remains a learning and research concept. It is not currently a proven secure product, does not guarantee anonymity merely because a code is used, and should not be described as military-grade.

### Cybersecurity and Model Safety

I want to explore authorized security research, AI red-teaming, and multilingual English–Bangla model-safety evaluation after building stronger foundations.

### Artificial Intelligence, Computer Vision, and Image Processing

I am learning Python and mathematics for academic work, machine learning, computer vision, and image processing. These remain developing areas rather than professional expertise.

### Hardware

Hardware was once something I described as intimidating. After building and administering Sparkle, the better description is:

> I am still early in hardware and electronics, but I am willing to work hands-on and no longer treat the area as something to avoid.

Future Raspberry Pi projects can gradually introduce GPIO, sensors, electronics, and physical automation with proper guidance and safety.

## How I Want to Build

A successful project does not need a huge audience. A tool built for myself that later helps four or five people is already worthwhile.

I want to:

- understand the problem before choosing technology;
- write and understand my own code;
- encounter and repair real errors;
- know why each important component exists;
- deploy projects rather than leave everything as local demonstrations;
- document enough that I or another learner can reproduce the work; and
- create useful work that can remain free when appropriate.

I use AI assistants as learning collaborators. They should support understanding, review, debugging, and deliberate practice—not quietly replace my work.
